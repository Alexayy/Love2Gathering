## Features used in this project

The implementation used parallel subagents with bounded ownership, coordinated by a main integration agent. Parallel subagents are a documented Codex workflow; each performs its own work and reports results to the parent. Shared file edits need deliberate ownership to avoid conflicts. [Official subagent documentation](https://learn.chatgpt.com/docs/agent-configuration/subagents).

| Workstream | Delegated work | Integration boundary |
| --- | --- | --- |
| Engine | Inspect XMage, compile the required modules, implement the Java transport and native prompt projection, exercise real rules and AI | JSON state/prompt contract and engine fixtures |
| Catalog and builder | Stream the JSONL into SQLite, implement search/storage/construction validation, extend builder controls and model contracts | Catalog endpoints, persisted deck shape and shared builder layout |

| Main agent | Coordinate requirements, review contracts, integrate the table, scaling, modals/settings and artwork, run the actual desktop client and inspect screenshots | Final application behavior and acceptance |

The work used shell commands for focused source discovery, builds and local runs; patches for reviewable edits; primary documentation and the supplied rules PDF for targeted checks; local image/asset inspection; real HTTP/service tests; deterministic engine fixtures; and actual LÖVE rendering with screenshots. The frontend uses LÖVE, Slab, a local Python service and XMage. Codex is a development tool, and the running client requires no OpenAI API key or OpenAI runtime API.

## Viewport, priority, theme and gallery follow-up

The table now opens on the human field at 1× world scale, rather than fitting every seat into miniature fields. Battlefield cards keep their world size, the header occupies about 104 logical pixels, and the terrain continues beneath a compact hand. Hover expands the hand and enlarges its focused card. Right-drag pans, the wheel zooms, and the overview is explicit. World/screen animation poses, card hits and scissors use separate but consistent coordinate spaces.

`PriorityController` asks XMage for meaningful native playable abilities and special actions, excludes native mana abilities alone, and uses native passing on the GAME thread. End Turn yields ordinary priority until a changed stack/turn, selected stop or required choice cancels it; normal empty-window automation then continues. The native playable calculation can conservatively retain a targetless action, so this is not a promise to suppress every possible extra question. An explicit stop or full control can retain empty priority for a bluff. UI stops use separate own/opponent indicators and an acknowledged gold status. The frontend blocks consumed prompt IDs during a pending command or when the native state says no priority is available; native snapshots must pair their prompt with the same current pending decision.

The Slab skin is an optional draw-command hook, preserving existing layout/input/clipping. Seven curated original PNGs use both provided Kenney packs, with original licenses and source paths. Full user-provided distributions remain untouched. `Theme.install` is applied from `View.new`, so all application views use the same skin. The fantasy divider is used beneath non-match navigation.

Gallery has per-printing and per-image-face credits, release year and variant filters. Only reviewed artist links are shown; unknown artists remain unlinked. That extension introduced API version 4 and `catalogSource` to prevent incompatible catalog reuse; the current launcher requires API 9. Missing metadata is explicit. Downloading full bulk metadata is opt-in and uses a new destination, preserving originals.
