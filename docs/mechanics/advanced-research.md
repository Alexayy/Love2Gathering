# Advanced mechanics research and native fixture scope

Reviewed 2026-11-15 against engine pin `d9b266fc981024873ac7ec5f90ee7121a060725e`. Engine sources were read only. The scenario contract is [advanced.json](../../bridge/tests/mechanics/advanced.json); executable resolution fixtures are [AdvancedMechanicsFixture.java](../../bridge/tests/love2gathering/AdvancedMechanicsFixture.java).

These are deterministic native resolution/identity tests. Test helpers establish initial zones and declared stack resources. They do not establish that a production deck can reach the position, and injected paid-X stack values do not prove mana-payment behavior. Real casting is used only where the scenario states it, including the optional sacrifice/return/cast-zero cycle. The runner records separate production-game and client evidence.

## Primary rules and reported issues

- [Wizards rules resources](https://magic.wizards.com/en/rules) supply the current Comprehensive Rules; merging, copy effects, replacement/prevention effects and loops are separate rule groups.
- [Official Ikoria release notes](https://magic.wizards.com/en/news/feature/ikoria-lair-behemoths-and-commander-2020-edition-release-notes-2020-04-10) describe mutation as the same permanent gaining merged components. Top characteristics and inherited abilities are copiable, while counters and marked damage are not copy effects. Mutation itself does not enter a new permanent; a target lost before resolution instead produces an ordinary entering creature. Leaving the battlefield separates the physical components. The fixture checks native IDs, component lists, current P/T and zone results separately.
- [Official M21 release notes](https://magic.wizards.com/en/news/feature/core-set-2021-and-jumpstart-release-notes-2020-06-20), Nine Lives notes, require an incarnation counter even when damage cannot be prevented. This provides a precise oracle for the Banefire/Skullcrack comparison rather than an expectation fitted to engine behavior.

## Derived cases

The cases below are explicit inferences from card/native operations and the relevant rules, then checked against actual engine state:

- Mutation plus counters, damage and tap state distinguishes object continuity from changing printed characteristics. Mutation plus blink/bounce/control change checks that the physical cards, owner and current controller are separate identities.
- Copying a merged token and copying a three-component creature test component/ability propagation independently of the original's mutable state. Retargeted spell copies, triggered copies and paid activated-ability copies have separate tests.
- Parallel Lives with Doubling Season checks one application per replacement effect. Academy Manufactor with Parallel Lives checks multiple token families and exact per-family counts. Vigor with Solemnity checks that prevention remains effective even when its counter instruction is prohibited.
- Nine Lives with Solemnity is treated as a working legal lock, not an infinite computation. Skullcrack and Banefire X=5 compare two native ways of making damage unpreventable while checking Nine Lives' additional counter instruction.
- Scute Swarm's sixth/seventh-land sequence is finite. The optional Renewal/Altar/Ornithopter and Kiki/Conscripts/Impact sequences require explicit activations and then use an offered native Pass to stop. Mandatory Sporemound/Life and Limb and Polyraptor/Marauding Raptor cycles are observed under resolution budgets; Stuffy Doll/Pariah's Shield distinguishes stable life/object counts from growing marked damage.

## Native loop and resource details

The pin's [GameImpl](https://github.com/magefree/mage/blob/d9b266fc981024873ac7ec5f90ee7121a060725e/Mage/src/main/java/mage/game/GameImpl.java) calls its native loop check from its protected `resolve` wrapper. Calling only `GameStack.resolve` misses that policy. This fixture invokes the actual wrapper using test-only reflection, then the ordinary native state/trigger checks. A native confirmation and actual native draw are recorded distinctly from a budget checkpoint. Revisions or repeated hashes do not decide an outcome.

The native `TokenImpl` at this pin has a 500-token-per-controller creation cap. This is an existing engine resource behavior, not a limit introduced by the frontend or this harness. Tests must report requested and actually created quantities separately. It does not demonstrate a universal machine/UI maximum.

Initial bare-session startup under the default high-core-count JVM settings exceeded the first 768 MiB test RSS budget. Those diagnostics remain in the initial run. The bounded final profile uses `-Xmx512m`, `-XX:ActiveProcessorCount=2` and a 1.5 GiB RSS budget. This change controls the test process; it does not change Magic decisions.

## Evidence and current findings

Each invocation writes `result.json`, offered-choice/action trace when relevant, an explicitly labeled native event-count summary, a separate retained structured log, and entitled projections into its unique owned run directory. A stateless test-only watcher counts actual fired GameEvents by type outside the native serialized state; it ignores simulations/playable-action calculation and survives bookmark copies. `lastNativeEvent` records the latest observed native event, while `nativeStructuredLogCount`, retained structured logs and the bounded animation window remain separate measurements. The outer runner captures process identity/resources and watchdog diagnostics. Critical mutation, copy and loop cases request at least three independent JVM runs.

The derived Banefire X=5/Nine Lives case initially produced native damage 5 with zero incarnation counters; the Skullcrack control produced native damage 3 with one counter. This is an engine-state discrepancy against the official ruling, not a frontend display assertion. No exact matching upstream report was found in the reviewed sources, so it is a **suspected upstream failure**, not a known upstream issue or a pass. The engine remains unchanged and the test preserves its original expected counter count.

The historical baseline, before the later control/projection/artwork and added legend/attachment cases, used 34 scenarios and 84 owned JVM invocations: 78 passed, three Polyraptor checkpoints reached the declared 24-resolution test budget, and all three Banefire repetitions failed with the same native counter discrepancy. Maximum sampled RSS was 690.2 MiB under the bounded profile. Sporemound/Life and Limb produced a native draw after 17 resolutions; Stuffy Doll/Pariah's Shield did so after 18. These are measured results of this fixture and pin, not universal loop thresholds. Polyraptor still had pending native work at its checkpoint; no outcome was assigned.

The focused two-human merged-token projection regression failed against the baseline bridge because component metadata was absent. The root's fresh `build-current-v2` bridge then passed 20 checks covering component IDs/order, original Bear template versus current Gemrazer printing, copy independence, public inspection and hidden/face-down redaction. Its fixture has a separate stable ID, `adv-mutate-projection-token`.

The historical baseline predates the Act of Treason strengthening of the control-change case. The consolidated fresh-source run at `executions/full-60661bd1` subsequently passed the corrected control case three times with 10 assertions each and the then-current projection case three times with 31 assertions each. The final v6 artwork/provenance extension passed three fresh projection runs with 42 assertions each under `heavy-final-v6`. Build/source hashes and all remaining findings are indexed in [the main report](../MECHANICS_REPORT.md) and [structured evidence](../../bridge/tests/mechanics-report.json); these later results do not rewrite the earlier baseline artifacts.

The earlier baseline artifacts used the field name `nativeEventCount` for the structured-log sequence. Those original files and hashes are preserved; that old field is not a raw-event measurement. Fresh acceptance reports use the instrumented watcher and an explicit `eventCountScope`. The native event budget is 10,000 for these small directed scenarios and is a test-abort boundary, never a rule or game outcome.

The merged-token projection fixture saves `visible-merged-frame.json` using the real session publication before copying or turning the merged creature face down. It is a full native entitled projection suitable for client replay/render checks, alongside the individual `visible-merged-card.json` metadata assertions.

Advanced results expose `nativeResolutions` for the identically named manifest budget. Test-only Java properties `love2gathering.test.stepSeconds`, `love2gathering.test.nativeEvents`, `love2gathering.test.acceptedActions` and `love2gathering.test.nativeResolutions` configure the per-task deadline and count ceilings, with defaults 12 seconds, 10,000 fired events, 100 accepted responses and 80 native resolutions. The result records the applied values in `appliedBudgets` and the applied `stepSeconds`; the earlier `fixedStepSeconds` metadata belongs only to its earlier source version. Task deadlines cancel the owned future and raise a test-budget result; count bounds never create a native game outcome. The external watchdog independently enforces total wall/resource budgets. `checksScope` states that injected pre-paid native spells cover resolution, not production casting or payment. The consolidated fresh-source run and final follow-ups record the applied default budgets. Nondefault diagnostic budget probes have their own scope; a future policy change requires fresh acceptance.

The projection artwork follow-up separates three native identities: a merged host's current Gemrazer/top printing, its original Bear `tokenTemplate`, and an ordinary Grizzly Bears token copy's exact native `copySourceCard` reference. The pinned `CopyTokenFunction` mutated-source branch copies characteristics and returns without calling `setCopySourceCard`; a copy of a merged creature therefore has unavailable original-card provenance. The fixture preserves that absence and forbids a name-based guess. An independent ordinary Grizzly Bears/Rite of Replication control asserts exact source-card UUID/name and no physical merged components. The final v6 projection follow-up passed these assertions as part of its three independent 42-assertion runs; earlier projection passes remain separate historical evidence.

The final copied-token-top edge merges a second Sea-Dasher Octopus under the ordinary copied Grizzly Bears token. It compares the native ordered host/component UUIDs and `Token.getCopySourceCard` with both the host's original normal-copy template and the top token component's projected provenance. The under component remains metadata on one existing native permanent, not an independent permanent target. `copied-token-top-card.json` retains the exact comparison and `copied-token-top-frame.json` saves the full visible native projection. These assertions passed the final v6 three-run projection acceptance, with 42 assertions in each independent JVM.

## Added legend and attachment/alternative-cost acceptance

Two final directed combinations close specific coverage gaps. `adv-copy-legend` enters Isamaru, Hound of Konda, resolves a native Rite of Replication copy and answers the actual legendary-rule keep prompt using the new token's offered UUID. The native SBA moves the physical original to its owner's graveyard and leaves one 2/2 copy with the expected owner and controller with exact source-card provenance and no merged components. It passed three fresh v6 JVMs with 14 assertions and one native UUID response each.

`adv-mutate-token-attachments` creates a native Bear token, establishes a Bonesplitter attachment through the native attachment API as explicit fixture preparation, and resolves a native Rancor Aura spell. It adds two native +1/+1 counters, one marked damage and tapped state. It then casts Gemrazer's actual native `MutateAbility` from hand with exactly three green fixture mana: native `{1}{G}{G}` payment consumes all three, although the printed cost is `{3}{G}`. This payment is not an injected pre-paid mutating spell. With the only eligible host, native targeting chooses the Bear automatically; no interactive UUID targeting response is claimed. The actual offered Over response is supplied during native resolution. The resulting live creature is 10/6, with the original Bear 2/2 template, both attachment IDs/host links, two counters, one marked damage, tap state and reach/trample retained. This establishes native alternate-cost payment and merge continuity; it does not establish production reachability or payment of the fixture Bonesplitter attachment/Rancor setup.

The attachment case passed three independent v6 JVMs with 24 assertions, one interactive Over response and 33 fired native events each. Both new scenarios' six external watchdogs passed and confirmed owned process termination; no GAME executor remained alive.
