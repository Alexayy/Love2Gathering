## Primary rules and rulings

The [official rules page](https://magic.wizards.com/en/rules) linked the [Comprehensive Rules effective 2026-11-06](https://media.wizards.com/2026/downloads/MagicCompRules%2020261106.txt) when reviewed. Relevant sections are 400.7 (zone-change objects), 601 (casting/cost payment), 603.3 (trigger placement/APNAP), 613 (continuous-effect layers), 701 (keyword actions), 608.2 (resolution/illegal targets), 510 (combat damage), 702.2/702.4/702.7/702.15/702.19 (deathtouch/double strike/first strike/lifelink/trample), and 704 (state-based actions). C07/C08 preserve zone-change identity; C13 checks actual two-human APNAP placement. C15/C16 separate a vanished confirmed blocker from trample permission. C17–C19 check native damage-step and keyword interactions, including explicit positive events rather than phase-based inferred hits. C33 verifies that countering a spell does not refund a paid additional discard cost.

The [official Foundations release notes](https://magic.wizards.com/en/news/feature/foundations-release-notes) describe Angel of Vitality's replacement applying once per life-gain event and its conditional boost updating before lethal-damage checks. C01 separates its printed 2/2 from live values and counters. C11 combines manual trigger ordering, two independent amplified life gains and Pridemate counters. C34 places Angel below threshold alongside an unblocked Vampire Nighthawk while Wind Drake blocks Angel: simultaneous lifelink must increase Angel's toughness before the first SBA. C35 reverses the situation: damage that was nonlethal becomes lethal after losing the threshold. These are specific combined test positions, not claims to new Magic rules.

## Fixture diagnostics and limits

Initial failures exposed test preparation mistakes rather than confirmed rules defects: setting life after Angel's replacement was installed changed the intended initial total; a ground Bear could not legally block a flying Nighthawk; and native manual pool payment needed the actual mana-pool flag in a fixture that bypassed normal `Game.start`.

The first C34 attempt also omitted `GameImpl.playPriority`'s initial `applyEffects()` after `CombatDamageStep.beginStep`. This incorrectly let the helper check stale toughness before SBA. The helper now follows the production phase boundary before checking native state. The rules expectation was unchanged and the failed evidence remains in the run directory. This case illustrates why a failing injected position alone is insufficient to classify an engine bug.

These are deterministic native fixtures: initial zones/resources use `Game.cheat`, and XMage executes the resulting operations. They do not show that a normally shuffled production game can reach every state, nor that a complete match ended. C24's Reef ability-wheel projection and C29/C30's hidden-target-label queries are explicitly projection subchecks; their remaining actions use real native mana/perspective state. Production games and actual LÖVE/input evidence are separate suites.

## Large values and variable characteristics

Its live values move from 1,000,002/1,000,002 to 1,000,005/1,000,005 and back; all one million counters remain. This is a bounded, injected arithmetic/event-volume test, not a claim about reachable production resources or a game-rule counter limit. The dedicated fired-event ceiling is 2,100,000; ordinary core cases retain a 1,000-event test ceiling.

C37 checks Tarmogoyf's characteristic-defining ability against card types across both graveyards, then moves the sole creature card to exile. Live values change from 3/4 to 2/3, while original native printing metadata stays unchanged. This distinguishes an actively recomputed value from a stale printing, counter total or catalog enrichment. The constructor's original numeric fields are retained as supplied by the pinned engine rather than invented Oracle text.

## Event and resource evidence

The test-only stateless `CoreNativeWatcher` counts fired GameEvents from each registered actual game after fixture initialization. It ignores simulation games and playable-action calculation, and reports per-type counts separately. Its state lives outside copied watcher objects so bookmark/AI copies cannot roll the evidence back. It does not count constructor setup or proposed events intercepted before firing. C36 observed 1,000,012 fired events, including 1,000,000 COUNTER_ADDED events, on its targeted baseline run.

`retainedAnimationEvents` is a different metric: it is the bounded public presentation window, which can contain at most the bridge's retained deque capacity. Production runs report the union of projected event IDs observed while polling or scanning saved frames; those counts must not be described as the full fired engine event stream. Every run also retains the external watchdog's wall time, RSS, CPU, output size and termination diagnostics. A passed rules assertion cannot turn a watchdog failure into a pass.

Normal production acceptance separately completed two damage-based duels and one deckout duel without concession, and verified their accepted-only contiguous recordings. Four- and six-seat Commander runs verified ordinary starts, all-seat rotation, privacy and confirmed termination; those partial games are explicitly not recorded as completed matches. Test replay exports use 50-row pages and lossless gzip JSONL, preserving all recorded rows without collecting a complete game in memory. This reduces evidence-export overhead; it does not change the application's authoritative SQLite recording format or promise bounded native game storage.

The current production runner distinguishes six policies: P01 burn mirror, P02 human burn against land-only control, P03 land-only control deckout, P06 human land-only control against the burn bot, followed by P04/P05 four/six-seat Commander rotation. The final v6 run completes all four duel policies with native outcomes; P01/P02/P06 pass recording checks, while P03 exceeds its original 30-second export-verification budget despite reaching native deckout. A separate read-only preserved-recording check passes under a declared 90-second ceiling. Four/six-seat Commander remains partial rotation evidence. Reaching three completed games does not convert the original P03 budget finding into a pass: every case retains its own status and the CLI fails if any required case fails.
